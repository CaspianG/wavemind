# WaveMind: цифровая память человека и компании

Дата: 2026-09-09. Базовая ревизия: `00192c3faed463e08e90a3e898fc84378b43a028`.

Статус: письменная спецификация подтверждена владельцем 2026-09-09.
Разрешена реализация D1 по отдельному плану с проверками. Все требования и
численные пороги ниже — цели, а не результаты, пока не опубликованы проверки.

## 1. Что должен получить пользователь

**Память остаётся у вас, даже когда меняется AI-помощник.** WaveMind хранит
контекст выбранных проектов, историю решений и проверенный опыт. Следующий
агент может продолжить работу, учитывая то, что уже известно и сделано.

Для человека: «Не объясняйте свой проект заново. Помощник сможет найти ваши
решения, актуальные ограничения и результаты прошлых попыток — с источниками».

Для компании: «Передавайте агентам историю работы с клиентом или проектом:
договорённости, изменения, ограничения и проверенные способы решения задач».

Это формулировки целевого продукта. До прохождения проверок их нельзя выдавать
за возможности опубликованной версии `2.14.0`.

Владелец поставил два равноправных требования: ощутимая ежедневная польза и
действительно удобная установка. «Почти как воздух» означает амбицию добиться
регулярной добровольной востребованности. Это не обещание универсальной
незаменимости, не требование искусственно ограничивать экспорт и не критерий,
который можно закрыть количеством тестов.

### Как выглядит первый полезный результат

| Человек | Компания |
|---|---|
| Загружает материалы одного личного проекта. | Загружает материалы одного клиентского кейса. |
| Видит актуальные решения, ограничения, незакрытые вопросы и источники. | Видит договорённости, смену условий, ответственность и историю действий. |
| Подключает другого помощника и продолжает проект без повторного рассказа. | Передаёт кейс другому агенту без потери разрешённого ему контекста. |
| Исправляет устаревшую информацию; следующий запрос учитывает исправление. | Меняет условие или отзывает доступ; старое правило больше не используется. |

Первый результат не равен «импортировано 100 файлов» или «нарисован граф».
Пользователь должен завершить конкретную задачу либо продолжить её с меньшим
количеством ручного восстановления контекста.

## 2. Решение и границы

Выбран независимый сервис памяти с общим ядром, интерфейсом владельца и
контрактом для агентов. Личный и командный режимы используют одинаковую
семантику памяти, но разные настройки доступа и развёртывания.

Рассмотренные альтернативы:

- Только SDK: минимальная интеграционная стоимость для разработчиков, но
  настройка и объяснение ценности остаются задачей каждого приложения.
- Отдельный универсальный AI-помощник: единый пользовательский интерфейс, но
  дополнительно нужны собственная оркестрация действий и управление моделями.
- Независимая память: требует хорошего подключения агентов, зато позволяет
  сохранять контекст при смене модели и приложения. Этот подход согласован.

«Весь контекст» означает контекст явно подключённых источников в пределах прав
доступа. Система не сканирует компьютер, почту, браузер или аккаунты целиком по
умолчанию. В интерфейсе всегда видны покрытие источников и свежесть данных.

Квантовый датчик не является зависимостью продукта. Прежние исследования,
протоколы, отрицательные результаты и опубликованные версии сохраняются.
Новая архитектура не меняет задним числом их выводы.

### Последовательность самостоятельных этапов

| Этап | Результат | Граница готовности |
|---|---|---|
| D1 — первый сквозной контур, подробно описан ниже | Общая память, локальный интерфейс, два сценария, подключение агента, проверка результата | Инженерный предварительный выпуск, не массовый продукт и не научное признание |
| D2 — установка для человека | Windows-приложение с мастером запуска, обновлением и удалением | Прохождение чистой установки и пользовательской проверки без помощи разработчика |
| D3 — командный пилот | Установка в инфраструктуре команды, права, резервное копирование, проверенное подключение агента | Ограниченный командный пилот; не заявление о готовности для любых предприятий |
| D4 — полезность и исследовательский метод | Продольные пользовательские проверки и отдельное сравнение нового метода | Измеренная польза и научный вклад имеют отдельные решения о допуске |

D1 — предмет следующего плана реализации. Для D2–D4 нужны собственные
технические спецификации, опирающиеся на результат D1. Эти этапы остаются
обязательными для общей задачи; завершение D1 не закрывает требование удобства.
Проверка понятности и первых полезных кейсов начинается на D1: D4 обозначает
итоговую программу доказательств, а не отсрочку общения с пользователями до
завершения всей разработки. При отсутствии пользы приоритеты следующих этапов
пересматриваются до расширения инфраструктуры.
Gmail, календари, CRM и другие живые коннекторы добавляются отдельными этапами
после проверки прав, синхронизации, удаления и условий обработки данных.

## 4. D1: архитектура первого контура

Новый пакет `wavemind/brain/` отделяет предметную модель от транспорта и UI.
Названия ниже — проектируемые модули, не уже существующие файлы.

| Модуль | Одна основная ответственность |
|---|---|
| `models.py` | Версионированные записи, состояния и пакеты контекста |
| `store.py` | Транзакции SQLite, журнал изменений, проекции и очередь интеграции |
| `access.py` | Проверка субъекта, пространства и разрешений на каждый источник |
| `sources.py` | Предпросмотр импорта, версии источника, ссылки на фрагменты |
| `reconcile.py` | Исправления, противоречия, сроки действия, зависимости |
| `context.py` | Сбор разрешённого актуального контекста под задачу и бюджет |
| `experience_bridge.py` | Связь пакета, действия, доказательства результата и существующего runtime |
| `service.py` | Прикладные операции, общие для CLI, HTTP и MCP |

Маршруты и UI подключаются небольшими отдельными модулями, а не большим новым
блоком в `api.py` или `studio.py`. Новый экран использует существующее приложение
FastAPI; отдельный микросервис, Kubernetes или графовая СУБД для D1 не нужны.

### 4.1. Источник истины и сохранность

В явно выбранном каталоге состояния создаётся `brain.sqlite3`. Она содержит
новые источники, утверждения, права, связи, журнал и очередь интеграции.
Существующие core/experience-базы не мигрируют неявно и не становятся копиями
истины для этих записей. Поисковый индекс — восстанавливаемая проекция.

Для опыта Brain используется отдельный экземпляр существующего хранилища в
`brain-experience.sqlite3`. Он не подключается к старым общим маршрутам чтения
опыта. Индексы Brain также приватны для нового сервиса: ограничение доступа
не должно обходиться запросом к старому `/query` или generic Experience API.
Переиспользуется код поиска и runtime, а не общий незащищённый набор данных.

D1 хранит данные в локальном профиле с правами текущего пользователя и не
обещает шифрование содержимого SQLite. Шифрование и управление ключами —
отдельный обязательный вопрос допуска чувствительных данных в D2/D3; до его
решения такой профиль явно ограничен несекретными пилотными материалами.

Изменение источника, его версии, прав и зависимых записей фиксируется одной
транзакцией этой базы. Производные индексы и опыт обновляются через устойчивую
очередь с идентификаторами операций. Между базами не обещается общая транзакция:
незавершённая интеграция видна как `pending`, а связанный опыт до завершения
не допускается к выдаче. Повтор операции не создаёт дубликатов.

Каждый пакет несёт ревизию памяти. Перед выдачей и повторным применением
проверяются актуальная ревизия, доступ и состояние зависимостей. Сбой индекса
допускает ограниченный поиск по авторитетному хранилищу с предупреждением;
сбой проверки доступа не допускает выдачу.

Backup и восстановление D1 охватывают новый источник истины и согласованный
срез связанного опыта: краткая приостановка записи, завершение либо сохранение
очереди, манифест снимка, проверка после восстановления. Если старые форматы
backup/upgrade этого не умеют, новый профиль обязан явно остановиться, а не
создать неполную «успешную» копию.

### 4.2. Записи и их смысл

| Запись | Обязательные свойства |
|---|---|
| `Brain` | Непрозрачный ID, владелец, режим personal/team, участники, политика хранения |
| `SourceVersion` | Brain ID, ID источника, версия, тип, время импорта, доступ, доступность, фрагменты |
| `Entity` | Явный ID и тип: человек, организация, проект, клиент или артефакт; ссылки на свидетельства |
| `Claim` | Тип, содержание, сущности, ссылки на фрагменты, время действия, время регистрации, статус, зависимости |
| `Relation` | Концы связи, тип, свидетельства, статус и зависимости; без безусловной метки «причина» |
| `ContextPacket` | Задача, субъект, ревизия, утверждения, опыт, цитаты, конфликты, пропуски, стоимость и срок применимости |
| `OutcomeLink` | ID пакета и его digest, ID действия/запуска, проверяющий, ссылки на доказательства, итог и статус интеграции |

Типы утверждений D1: факт, цель, ограничение, решение, обязательство. Опыт
действий остаётся в существующей модели процедур и не маскируется под факт.
Типы отношений D1: относится к, заменяет, зависит от, обосновано решением,
действие завершилось результатом. Последние два типа описывают свидетельства,
а не автоматически установленный причинный эффект.

Время действия и время получения информации различаются. Интервалы действия
полуоткрытые `[valid_from, valid_until)`; неизвестные границы остаются неизвестными.
Порядок получения не заменяет порядок событий. Одинаковые имена не объединяют
людей автоматически; неопределённая идентичность требует подтверждения.
Полуоткрытые интервалы относятся только к новому контракту Brain; семантика
интервалов существующих научных протоколов остаётся прежней.

Статусы утверждения: `proposed`, `active`, `conflicted`, `superseded`, `revoked`.
Активность означает допустимость использования в заявленной области, а не
гарантию объективной истины. Ответ всегда сохраняет происхождение утверждения.

### 4.3. Импорт и обновление

1. Владелец выбирает отдельные файлы, вставляет текст или импортирует историю.
2. Предпросмотр показывает объём, распознанный формат, предполагаемое пространство,
   доступ, предупреждения и то, будет ли содержимое передано модели.
3. Подтверждение создаёт версию источника и ссылки на фрагменты. Для D1 поддержаны
   UTF-8 TXT/Markdown, PDF с извлекаемым текстом и версионированный JSON сообщений.
   Произвольные экспорты не объявляются поддержанными без соответствующего адаптера.
4. Точный текст доступен для поиска. Извлечённые моделью структурированные
   утверждения поступают как предложения со ссылками на конкретные фрагменты.
5. Владелец подтверждает предложения либо доверенный структурированный адаптер
   создаёт записи в пределах явно заданного контракта. Это согласие не означает
   подтверждения причинности или эффективности действия.
6. Повторный импорт той же версии идемпотентен. Обновление создаёт новую версию
   того же источника после явного выбора, а не угадывания по имени файла.

Без подключённой модели доступны импорт, поиск, просмотр, ручные исправления
и сбор пакета. Автоматическое извлечение из произвольной речи требует явно
подключённого агента/модели; отсутствие такой связи видно в интерфейсе.
Система не выдает шаблонный текст за ответ работающей модели.

Начальные лимиты D1: 20 файлов за импорт, 10 MiB на файл, 50 MiB на весь импорт,
2 MiB извлечённого UTF-8 текста и 30 секунд парсинга на файл. Превышение даёт
явный отказ по файлу; частичный результат принимается только после просмотра.
D1 не принимает архивы, не выполняет содержимое файлов, не обходит
символические ссылки и не читает произвольные серверные пути по HTTP.
Сканированный или защищённый PDF получает объяснимый статус неподдержанного
содержимого; пустой импорт не становится успешной памятью.

### 4.4. Исправление, отсутствие данных и удаление

Явное исправление указывает заменяемое утверждение и область действия. При
несовместимых утверждениях с пересекающимися интервалами система показывает
конфликт; более поздний импорт сам по себе не назначает победителя.
Исправление, пришедшее раньше своей исходной записи, остаётся предложением
в своём Brain до разрешения ссылки. Оно не создаёт разрешения на чужую запись;
после получения всех допустимых событий итоговое состояние должно совпадать
с обычным порядком. Конкурирующие исправления требуют явного решения владельца.

Изменение или отзыв исходного утверждения делает зависящие от него выводы и
процедуры недопустимыми до перепроверки. Обход зависимостей ограничен, циклы
обнаруживаются; незавершённый пересчёт означает `pending`, а не сохранение
старого вывода как актуального. D1 выбирает безопасную повторную проверку
затронутого вывода, а не сложное доказательство альтернативных оснований.

«Отключить синхронизацию», «запретить выдачу источника» и «удалить сохранённые
данные» — разные действия. Первое сохраняет снимок с отметкой свежести, второе
немедленно блокирует будущую выдачу, третье удаляет содержимое и производные
тексты из обслуживаемого состояния, индексов и очередей. Источник на диске
пользователя не удаляется. Область удаления показывается до подтверждения.

Журнал хранит минимальные непрозрачные идентификаторы и типы операций; удалённый
текст, цитаты и восстанавливающие их payload не сохраняются в «неизменяемом»
аудите. Резервные копии имеют отдельное видимое хранение. Восстановление старого
снимка требует сверки с доступным актуальным журналом отзывов и удаления;
если журнала нет, восстановленные источники не выдаются до повторного допуска
владельцем. Уже отправленные внешнему агенту данные нельзя обещать отозвать из
его истории: это ограничение сообщается при подключении.
Удаление обслуживаемого состояния не является обещанием невосстановимого
стирания свободных страниц SQLite или физического носителя. Остаточные копии,
резервные снимки и защита ключей описываются отдельно от кнопки отзыва доступа.

### 4.5. Доступ и подключение агентов

Для Brain API доступ проверяется по точным ID пространства и источника, а не
только по строковому префиксу namespace. На каждом чтении, поиске, цитировании,
экспорте и запросе истории применяются одни и те же проверки. Недоступный
источник не раскрывается через заголовок, счётчик, граф, текст ошибки или кэш.
Производная запись требует доступа ко всем использованным в ней источникам.

Роли D1: владелец, редактор, читатель. Отдельное подключение агента получает
ограниченный токен, выбранные пространства и разрешённые операции. Право
предлагать факты или отправлять результат не даёт права изменять доступ,
удалять память либо подтверждать собственную эффективность.

Текст источника и предложенные моделью связи считаются недоверенными данными.
Инструкции внутри документа не меняют права, правила проверки или поведение
сервиса. Пакет явно отделяет содержимое источников от управляющего контракта;
для атак через сохранённую память используются проверки существующего firewall.

Даже локальный UI использует аутентифицированную сессию. Только loopback-bind
не считается достаточной защитой: проверяются Origin/Host и защита изменений
от межсайтовых запросов; токены не помещаются в URL и диагностические логи.
Для командного доступа вне loopback обязательны аутентификация и TLS.

Новый прикладной контракт един для HTTP и MCP: `preview_import`,
`commit_import`, `propose_claims`, `review_claims`, `build_context`,
`read_citation`, `record_outcome`, `review_memory`, `export_brain`.
Транспорт проверяет полномочия до обращения к сервису; сервис повторно
проверяет предметные ограничения. Версия нового пакета — `wavemind.brain_context.v1`;
существующий `ExperiencePacket` не изменяется несовместимым образом.

Задача на сбор контекста включает Brain ID, проект/кейс, вопрос, момент времени
и бюджет. Субъект берётся из аутентифицированного соединения, не из доверенного
пользовательского поля. Выход разделяет актуальные записи, разрешённые цитаты,
применимый опыт, конфликты и недостающие сведения. Ограничение бюджета не
разрешает обрезать цитату так, чтобы потерялось её происхождение.

### 4.6. Обучение и граница причинности

До действия создаётся квитанция использования конкретной версии пакета.
После действия результат связывается с этой квитанцией и принимается только
через настроенный проверяющий адаптер или явное подтверждение владельца.
Произвольный JSON с надписью `test` не является независимым доказательством.

Проверка связывает артефакт, запуск, результат и полномочия проверяющего.
Повтор квитанции не увеличивает число независимых наблюдений. Непроверенные,
противоречивые и незавершённые результаты остаются видимыми, но не повышают
доверие к процедуре. Существующая политика продвижения опыта сохраняется;
для будущего применения дополнительно проверяются зависимости от Brain.

Подтверждение «действие завершилось успешно» не доказывает, что именно память
вызвала успех. `CausalUtilityController` остаётся отдельным экспериментальным
сравнением. Для причинного вывода нужны подходящий дизайн вмешательства или
идентифицируемая модель с объявленными предпосылками, а не совпадение событий.
Обучение D1 меняет записи и допуск процедур; оно не дообучает веса модели.

## 5. Сквозные сценарии D1

### P1. Личный проект после перерыва и смены помощника

Пользователь добавляет заметки о проекте и историю разговора. Он подтверждает
цель, два ограничения и принятое решение. Позднее исправляет одно ограничение,
но оставляет историю доступной. После перезапуска другой клиент агента
получает пакет с новой версией, обоснованием решения и открытым вопросом.

Агент готовит следующий шаг. Пользователь видит использованные источники,
исправляет предложение при необходимости и фиксирует результат. На следующем
обращении проверенный опыт доступен только в подходящей области действия.
Удаление одного источника исключает зависящие от него тексты из новых пакетов.

### B1. Передача клиентского кейса другому агенту

Команда добавляет условия обслуживания, переписку и историю выполненных задач.
Агент A получает контекст разрешённого клиента, предлагает действие и сохраняет
проверенный результат. Условия затем изменяются явным исправлением. Агент B
получает актуальные условия и историю изменения; старый способ работы требует
перепроверки, если изменилось его основание.

Другой клиент и внутренний закрытый источник добавлены как отрицательный
контроль. Агент B не получает их содержание ни напрямую, ни через производный
вывод. Отзыв доступа действует и для ранее закэшированных пакетов. При сбое
проверяющего система показывает «результат не подтверждён».

Оба сценария выполняются одним сервисом и общими контрактами. Подмена имён,
порядка импорта и содержания не должна ломать поведение: реализация не может
распознавать заранее написанную историю как специальный демосценарий.

## 6. Интерфейс и установка как часть продукта

Первый экран объясняет результат до терминов «граф», «namespace» или «эмбеддинг».
Основные разделы: «Проекты», «Что известно», «Что изменилось», «Опыт»,
«Источники и доступ». Режимы personal/team не смешивают приватные пространства.
Первый интерфейс и объяснение продукта доступны на русском и английском;
это не означает проверенное качество извлечения на любых языках.

Мастер D1: выбрать режим и проект; добавить источник с предпросмотром;
просмотреть/подтвердить найденные сведения; собрать первый контекст;
подключить агента и выполнить проверочный запрос. На шагах видны прогресс,
стоимость внешней обработки, отмена и понятное исправление ошибки.
Встроенный пример помечен как пример и отделён от собственных данных.

Первое подключение агента проходит реальную проверку чтения разрешённой
цитаты. Надпись «подключён» не появляется после простого копирования конфигурации.
Изменение настроек стороннего клиента требует явного согласия и резервной
копии затрагиваемого файла. D1 поддерживает документированный HTTP-клиент и
MCP-контракт; массовый мастер D2 обязан проверить конкретный поддерживаемый
клиент, а не объявлять совместимость со всеми помощниками.

### Контракт удобства D2 и D3

- Личный первый выпуск ориентирован на Windows 11 x64. Установщик для текущего
  пользователя содержит нужный runtime; Python, Git, Node и Docker не требуются.
  Другие платформы не заявляются поддержанными до собственной проверки.
- Запуск из ярлыка открывает локальное приложение. Ручное редактирование JSON,
  портов и переменных окружения не является обычным пользовательским путём.
  Необязательная автозагрузка выключена по умолчанию.
- Без GPU и внешнего API-ключа работают хранение, просмотр и проверка пакетов.
  Подключение AI и возможная оплата модели объясняются отдельно, до отправки данных.
- Установщик показывает версию, источник, объём и каталог данных. Для публичного
  массового выпуска необходимы подтверждённый издатель/подписание и проверенная
  цепочка обновления. Подписание, сертификаты и их покупка этим документом не
  считаются выполненными или автоматически разрешёнными расходами.
- Обновление создаёт проверенную резервную копию нового состояния и умеет
  откатить неудачную миграцию. Удаление программы по умолчанию сохраняет память;
  удаление данных — отдельный понятный выбор.
- Командный первый выпуск — один сервер в инфраструктуре команды, постоянный
  том и установочный мастер для администратора. Предварительная проверка
  объясняет требуемые ресурсы, TLS, доступ, состояние хранилища и backup.
- D3 использует отдельную установку для каждой организации. Общий публичный
  multi-tenant SaaS, SSO, высокая доступность и нормативное соответствие не
  подразумеваются наличием namespace; для них нужны отдельные спецификации.

Проектируемые команды вроде `wavemind brain start` должны маркироваться в
документации как будущие, пока не реализованы и не проверены. Существующий
`pip install wavemind` не рекламируется как способ получить новый контур.

## 7. Проверки и измерение настоящей пользы

### Инженерная приёмка D1

Каждая строка должна иметь воспроизводимый тест и проверку через публичный
контракт; отрицательные случаи не заменяются проверкой наличия поля.

| ID | Проверяемое требование |
|---|---|
| F01 | Источники, решения, доступ и опыт переживают перезапуск процесса. |
| F02 | Повтор импорта, результата и повтор после сбоя не создают дубликатов. |
| F03 | Явное исправление учитывается независимо от порядка получения событий. |
| F04 | Неявный конфликт не разрешается без основания; неопределённость видна. |

### Пользовательская приёмка, отдельная от тестов кода

Числа здесь — начальные пороги допуска ограниченного пилота, не доказательство
массового спроса. Перед пилотом фиксируются задания, измерения и правила
исключения; после наблюдения результата пороги не ослабляются.

- **Установка:** чистая Windows VM без инструментов разработчика проходит
  установку, первый запуск, обновление, восстановление после сбоя и удаление.
  Отдельно проверяется минимальная заявленная конфигурация командного сервера.
- **Понятность:** минимум 10 новых участников личного пилота; минимум 8 без
  подсказки разработчика объясняют пользу, какие данные доступны системе и
  как исправить/удалить память. Это качественный пилот, не репрезентативная выборка.
- **Первый результат:** у личного пилота медиана не более 5 минут и не менее
  8 из 10 завершений за 10 минут после запуска до первого подтверждённого пакета
  на собственном источнике до 20 KiB извлечённого текста. В пакете участник
  проверяет актуальное решение/ограничение и его источник. Время загрузки/установки учитывается
  отдельно и также публикуется; нельзя прятать его в этих пяти минутах.
- **Повторная польза:** наблюдение 14 дней. Начальный порог личного пилота —
  минимум 6 из 10 участников добровольно продолжают свой проект ещё в два
  разных дня и каждый фиксирует хотя бы один завершённый шаг с полезным
  восстановленным контекстом. Учитываются также лишние исправления, ошибочные
  советы и время проверки источников; возврат без результата не считается пользой.
- **Команда:** минимум 3 добровольных командных пилота перед заявлением о
  подтверждённой командной пользе. В каждой — передача минимум 3 реальных
  кейсов между исполнителями/агентами с разрешёнными данными и учётом затрат.
  Первоначальный порог — минимум 2 из 3 команд получают подтверждённо полезную
  передачу во всех трёх кейсах и выбирают продолжить пилот. Полезность оценивает
  принимающий исполнитель по выполнению заранее заданного следующего шага,
  необходимым исправлениям и общей затрате времени; снижение качества не
  засчитывается как экономия. Это сигнал пилота, не причинная оценка эффекта.
- **Решение о развитии:** личная и командная полезность сообщаются отдельно.
  Отрицательный результат одной аудитории нельзя скрыть средней цифрой двух.
  Интервью, добровольные возвраты и выполненные задачи важнее числа загруженных
  записей; ни один из этих сигналов сам по себе не означает «нужен всем».

Участники и разрешённые реальные данные пока не предоставлены. Их отсутствие
не мешает разработке D1, но не позволяет объявить пользовательскую приёмку
выполненной. Этот документ не разрешает рассылки, сбор чужих данных или
запуск платных экспериментов без соответствующего согласования.

### Научная проверка

Исследовательский вопрос: какие элементы памяти помогают успешно продолжать
задачи при изменении условий и ограниченном контексте, и когда их применение
нужно остановить? Это направление поиска, а не утверждение, что новый метод
уже найден. Функции D1 не объявляются научной новизной.

Отдельный протокол D4 должен сравнивать одинаковых агентов с одинаковыми
исходными данными и инструментами: без долговременной памяти, с обычным
поиском, с сильной существующей системой памяти и с новым кандидатом.
Отключение WaveMind не лишает контрольную группу исходных документов.

Считаются успешность новых задач, повторные ошибки, ручные исправления,
устаревшие советы, утечки, задержка и полная стоимость чтения/создания/обновления
памяти. Замеры включают разные соотношения записей и чтений; стоимость записи
не объявляется бесплатной. Отдельно измеряется деградация при недоступности памяти.

Данные разделяются по людям/организациям/проектам и времени до оценки. Нужны
непросмотренная финальная выборка, независимая оценка исхода, фиксированные
бюджеты, абляции, доверительные интервалы и сохранение всех отрицательных строк.
Пороги эффективности задаются в новом протоколе до запусков с учётом мощности
выборки; этот документ не переоткрывает старые неудачные финальные выборки.
Новизна, воспроизводимость, прикладная польза и работоспособность имеют разные
статусы. Наличие валидатора и зелёного CI не подменяет ни один из них.
